# Библиотека иллюстраций «один тезис — один кадр» (INF-15 «Полотно»)

**Дата:** 28.07.2026 · **Статус:** пилот из 5 ассетов собран, остальные ждут решения
**Сборщик:** `tools/assets_grid.py` · **Выход:** `build/assets/grid/`

---

## 1. Почему идея правильная

Сейчас у нас три отдельные вещи, которые делают одно и то же тремя способами:
страница исследования, текст поста и ролик. Каждая со своими числами (сверяются
вручную), своим кодом и своей вёрсткой. Пост при этом вообще без иллюстраций —
тринадцать тысяч знаков сплошного текста.

Предложение переворачивает порядок: **сначала библиотека кадров, потом всё
остальное собирается из неё.** Что это даёт:

- **Статья получает иллюстрации.** Каждый тезис — со своим доказательством в
  картинке, а не только в предложении.
- **Ролик перестаёт быть отдельным произведением.** Он становится плейлистом:
  порядок ассетов плюс хронометраж. Монтаж — это правка манифеста, а не правка
  кода рендера.
- **Числа сходятся по построению.** Один источник — `grid.json` и
  `grid_story.json`; ассет читает их в момент рендера. Расхождение поста, страницы
  и ролика становится физически невозможным.
- **Ошибка чинится точечно.** Сейчас правка одного числа означает перерендер
  всего ролика. В библиотеке — перерендер одного кадра.
- **Ассеты переиспользуются:** карточки для соцсетей, слайды для выступления,
  превью для страницы, иллюстрации для прессы. Один раз собрал — четыре раза
  применил.
- **Это укладывается в стандарт проекта.** Каждый кадр — детерминированный
  артефакт из данных, а не картинка, нарисованная руками. Проверяемо, как всё
  остальное.

## 2. Где идея может испортиться (и как этого не допустить)

| Риск | Защита |
|---|---|
| Иллюстрация ради иллюстрации: график там, где хватило бы числа | Правило: визуал обязан **нести доказательство**, а не украшать. Если тезис доказывается одним числом — ассет и есть число крупно, а не выдуманная диаграмма |
| Двадцать кадров выглядят как двадцать разных проектов | Один сборщик, одна сетка, одна палитра, единая шапка и обязательная строка источника внизу каждого кадра |
| Кадр вырван из контекста и превращается в дезинформацию | Каждый ассет самодостаточен: заголовок + источник + бейдж «ДАННЫЕ» или «МОДЕЛЬ» прямо в кадре. Скриншот любого кадра остаётся честным |
| Ролик распадается на набор слайдов | Часть ассетов делается анимированными (таймлапсы, разрыв ткани), плюс сквозной порядок повествования — библиотека не отменяет драматургию |

## 3. Что изменилось в вёрстке по сравнению с прошлым роликом

Прошлая версия была 1920×1080 по пикселям, но всё содержимое стояло в узкой
центральной колонке — визуально это читалось как вертикальное видео с тёмными
полями. Претензия справедливая.

Новая композиция — **полноэкранная 16:9**: визуал слева на всю высоту кадра
(960×850), тезис и график справа (752 px), шапка и строка источника на всю
ширину. Кадр работает как разворот, а не как вертикаль в рамке.

Для ленты Facebook и Instagram под кадрирование 4:5 будет отдельный экспорт из
той же библиотеки — с перестановкой блоков (визуал сверху, текст снизу), а не
обрезкой горизонтального кадра.

## 4. Пилот: пять кадров

| id | Тезис | Тип визуала | Источник чисел |
|---|---|---|---|
| `rule500` | Правило пятисот: граница роста и убыли на 500 чел/км² | карта подсветки классов + дивергентная диаграмма из 5 столбиков | `c004_density_bands` |
| `matrix` | Держит не вода и не асфальт, а их пересечение | карта четырёх групп + диаграмма из 3 столбиков | `c006_river_road_matrix`, `c007_river_distance` |
| `voids` | Три разные пустоты: чернобыльская, западная, полесская | карта 2020 с тремя рамками + нумерованный список районов | `raions.shrunk_most` |
| `islands` | Полотно рвётся на лоскуты | два кадра рядом (1975 наблюдение / 2050 модель) + hero-число | `national.settlement_components` |
| `nightlights` | Проверка независимым сенсором не пройдена | bullet-график «факт против заранее объявленного порога» + три карточки | `validation.g3_nightlights_crosscheck` |

Плюс один анимированный: `islands_motion.mp4` — те же острова, 1975 → 2050,
одиннадцать кадров по 1,1 с. Показывает, как в библиотеке живёт тип «движение».

Формы выбраны по задаче данных, а не по привычке: где сравниваются величины со
знаком — дивергентные столбики от общего нуля (тёплый цвет — убыль, холодный —
рост, нейтраль = сама ось); где одно число против порога — bullet, а не круговая
диаграмма; где важна не величина, а сам факт разрыва — две карты рядом и число
крупно. Значения подписаны текстовым цветом, не цветом столбика; цвет несёт
только знак.

## 5. Остальные пятнадцать (после утверждения пилота)

**Экспозиция:** `cover` (страна 2020 + два числа парадокса) · `paradox` (+0,7% против
99 районов) · `grid_vs_raion` (район одним цветом против той же территории по
клеткам) · `half598` (половина страны на 598 км²).

**Аргументация:** `roads` (пояса от магистрали) · `rivers` (буфер 5 км + пояса) ·
`cities_check` (197 городов: медианы −6,8% против −31,5%) · `moved` (Минская
агломерация 1975→2020, анимация).

**Следствия:** `network_per_capita` (хороплет + ρ = −0,75) · `pension_link`
(работающих на пожилого, из INF-13) · `service_math` (механика исчезновения
услуги — схема, не график).

**Будущее:** `future_timelapse` (2026–2050, анимация) · `even_best_shrinks`
(−21,3% у лучшей группы) · `conclusions` (три вывода) · `verify` (финал «не верьте,
проверьте» + ссылка).

Итого двадцать. Ролик собирается из четырнадцати-шестнадцати; остальные живут
только в статье.

## 6. Как из библиотеки собирается ролик

```
build/assets/grid/<id>.png            статичные кадры
build/assets/grid/<id>_motion.mp4     анимированные
tools/reel_grid_manifest.json         порядок + хронометраж + переходы
tools/build_reel.py                   склейка через ffmpeg concat
```

Манифест — простой список: `[{id, seconds, transition}]`. Поменять порядок сцен,
выкинуть слабую, удлинить сильную — это правка одной строки JSON, без перерендера
кадров. Разные версии (полная 80 с, короткая 45 с, версия под 4:5) — это разные
манифесты над одной библиотекой.

## 7. Что нужно решить до продолжения

1. **Смотрится ли визуальный язык.** Пять кадров приложены — если сетка,
   типографика и цвет устраивают, остальные пятнадцать делаются по этому же
   шаблону без обсуждения каждого.
2. **Сколько кадров делать анимированными.** Моё предложение: четыре
   (`islands`, `moved`, `future_timelapse`, `cover`), остальные статичные. Анимация
   дороже и в статье всё равно не нужна.
3. **Нужен ли экспорт 4:5 сразу** или сначала собираем горизонтальную версию, а
   ленту закрываем позже.

## 8. Запуск

```bash
python tools/assets_grid.py --all              # все статичные кадры
python tools/assets_grid.py --id rule500       # один кадр
python tools/assets_grid.py --all --motion     # + анимированные
```

Требуется Pillow и ffmpeg. Шрифт — вендоренный `DejaVuSans.ttf`, тот же, что у
остальных визуальных материалов проекта.

Перед публикацией любого кадра действует то же правило, что и для страницы: числа
должны попасть в `checks/expected_results.json`, а при изменении данных ассеты
перерендериваются одной командой, а не правятся руками.
