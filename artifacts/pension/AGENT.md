# Инструкция для ИИ-агента: аудит пакета INF-13 «Кто кого содержит»

Ты работаешь с проверяемым пакетом исследования. Всё, что заявлено на
лендинге, обязано воспроизводиться отсюда одной командой. Твоя роль —
независимый аудитор: проверить источники, воспроизвести расчёт, вручную
пересчитать пороговые метрики, провести стресс-тест допущений (прежде всего
условной денежной арифметики CG) и вернуть машиночитаемый отчёт.

## Контекст

Главный результат: национальный коэффициент поддержки (SR) снижается с
**2,73** (перепись 2009) до **1,68** (прогноз 2046) и **1,41** (2056); к 2046
году под порогом SR<1,5 — **69 из 118** районов (58,5%), против **1 из 118**
уже в 2009 году (Кореличский район, SR=1,48 — расхождение с буквой
пререгистрации, ожидавшей ноль районов; см. `LIMITATIONS.md`, п. h). Три
оговорки, без которых вывод недействителен и которые ты обязан проверить:

1. `contribution_gap` (CG) — условный сравнительный индекс, ВСЕГДА класс
   MODEL, целиком: ни получатели пенсий района, ни занятость 2031+, ни
   зарплата/пенсия прогнозных лет не наблюдаются напрямую. ФСЗН —
   общереспубликанский фонд; отдельных территориальных пенсионных балансов
   на уровне района не существует и они не публикуются.
2. `crossing_year` района публикуется ИНТЕРВАЛОМ («до 2035»/«2035-2045»/
   «после 2045»), не датой — гейт G-3 (независимый бэктест) не пройден на
   районном уровне (доля верного знака 73,7% при требуемых 80%).
3. Гейт G-4 (сверка с UN WPP 2024) формально вне допуска (расхождение
   30,3%) — объяснение (другая граница трудоспособности UN) обязательно и
   дано, это не ошибка расчёта.

Канонические числа — `data/final/computed_results.json` (14 контрольных
метрик); контрольные значения с допусками — `checks/expected_results.json`;
все допущения — `params/assumptions.yaml`; границы применимости —
`LIMITATIONS.md`; полная классификация утверждений — `claims.yaml`. Пути
ниже — относительно корня пакета `artifacts/pension/`.

## Задача 1 — проверка источников

Два уровня происхождения (`sources/registry.csv`):

1. **Завендоренные входы** (`data/curated/*`, `data/raw/*`,
   `web/public/data/pyramids.json`, `sources/raw/*`) — их sha256
   зафиксированы в `checks/checksums.sha256`:

   ```bash
   cd artifacts/pension
   shasum -a 256 -c checks/checksums.sha256      # или: sha256sum -c
   ```

   Ожидаемо: все строки `OK`. Любое `FAILED` — дефект пакета.

2. **Живые URL** (`sources/registry.csv`, поле `url`) — dataportal Белстата,
   официальный портал Президента, myfin.by, OWID. При недоступности источника
   сверься с завендоренной копией (`sources/raw/*` для документальных PDF/HTML,
   `data/raw/pension/*.json` для API-выгрузок); при НЕСОВПАДЕНИИ (источник
   изменился после даты обращения 2026-07-26) — зафиксируй как расхождение
   происхождения, не как ошибку пакета. Обрати внимание: `un_psr=2.18` в
   `etl/pension.py:gate_g4()` — величина, ВЫВЕДЕННАЯ из сырых численностей
   OWID/UN WPP (см. PROVENANCE.md), а не скопированная готовым значением;
   пересчитай `(3876755+1528760-948561)/2046308` и сверь с 2,18.

## Задача 2 — воспроизведение

```bash
cd artifacts/pension
bash code/run.sh          # Python >= 3.10 + PyYAML (code/requirements.lock)
```

Скрипт (1) пересчитывает `web/public/data/pension.json` из вендоренных
источников (`python -m etl.pension`), (2) прогоняет инварианты
(`checks/tests/test_invariants.py`), (3) сверяет 14 контрольных метрик с
`checks/expected_results.json` (`code/verify.py`). Проверь **код выхода**
(0 = совпало) и что `web/public/data/pension.json` детерминирован (повторный
запуск даёт байт-в-байт тот же файл — случайности в коде нет, `seed: null`
в `manifest.json`).

Ручной пересчёт (минимум 3 района, формула — METHODS.md §4.1):

```python
import json
d = json.loads(open('web/public/data/pension.json').read())
kar = d['territories']['r-karelicki']
years = d['years']['territory']
print(dict(zip(years, kar['sr']['as_is']['base:official'])))
# ожидаемо: 2009 -> 1.48, 2019 -> 1.48, 2046 -> 1.05
```

Сверь `raions_below_1_5_2009` (ожидаемо 1) и `raions_below_1_5_2046`
(ожидаемо 69) независимым подсчётом по `web/public/data/pension.json` —
не полагаясь на `code/verify.py`:

```python
raions = [k for k in d['territories'] if k.startswith('r-')]
def below(year, thr=1.5):
    i = years.index(year)
    return sum(1 for r in raions
               if (d['territories'][r]['sr']['as_is']['base:official'][i] or 99) < thr)
print(below(2009), below(2046))
```

## Задача 3 — стресс-тест допущений (`params/assumptions.yaml`)

Перед каждым перезапуском с правкой кода удаляй байткод-кэш
(`rm -rf etl/__pycache__ etl/forecast/__pycache__`).

- **Порог трудоспособности A(t)**: замени вариант `as_is` на `65_60` в
  вызове `sr_tdr(..., policy=...)` (или временно поменяй местами константы
  в `POLICY_AGE`) и пересчитай национальный `crossing_year(1,5)`.
  Ожидание: год перехода сдвигается ПОЗЖЕ (выше возрастная граница -> больше
  людей считаются работающими -> SR выше при том же демографическом составе);
  сдвиг на уровне районов, где `crossing_year_as_is(1,5) <= 2056`, в среднем
  ≈9,2 года (медиана 9,0), но у 27 из 93 таких районов переход «отменяется»
  в пределах горизонта 2056 года (`policy_delta` становится `null`) — это
  ОЖИДАЕМЫЙ и задокументированный результат (H3 частично опровергнута,
  `LIMITATIONS.md` п. l), а не дефект пакета.
- **Чувствительность CG (гейт G-5)**: пересчитай `build_cg(...,
  k_multiplier=1.10)` и `k_multiplier=0.90`, `b_multiplier=1.10/0.90` (см.
  `etl/pension.py:gate_g5`). Ожидание: доля районов с сохранённым знаком
  (CG>=1 / CG<1) — не ниже 96,5% по любому из 4 вариантов (порог 90%).
  Знак Кореличского района (CG_2046=0,53 < 1) должен сохраняться при всех
  четырёх вариантах.
- **k_oblast (коэффициент охвата)**: замени `coverage_k_oblast(ref_year=2019)`
  на другой опорный год (если есть данные) — величина CG сместится
  пропорционально, но ранжирование районов внутри области сохранится (все
  районы одной области используют один и тот же `k_oblast`).
- **Ставка занятости 2031+**: `build_cg()` переносит ставку 2024 года без
  изменения на все прогнозные годы — попробуй заменить на ставку любого
  другого наблюдаемого года и проверь чувствительность знака CG к этому
  выбору (не покрыто гейтом G-5 буквально, но методически аналогично).
- **Гейт G-3 (порог верного знака 80%)**: попробуй ослабить порог до 70% в
  `if not (g3['beats_naive'] and g3['correct_sign_share'] >= 0.80)` -
  результат гейта изменится на «пройдена», но САМ расчёт (`mape_model=8.86%`,
  `correct_sign_share=73.7%`) не изменится - это иллюстрирует, что
  интервализация `crossing_year` района - решение о ПОРОГЕ публикации,
  зафиксированном ДО расчёта в пререгистрации, а не о качестве самой
  survival-only проекции.

## Границы (что пакет НЕ утверждает)

- **CG — не факт.** Ни один компонент формулы не наблюдается на уровне
  района; это индекс для межрайонного сравнения, не показатель реальных
  денежных потоков (`LIMITATIONS.md`, п. a-d).
- **crossing_year района — интервал.** G-3 не пройдена; точная дата на
  уровне района не заявляется и не должна интерпретироваться как таковая.
- **H1/H2/H3 — не подтверждены буквально.** H1: в 2009 году был один район
  ниже порога, не ноль. H2: рост межрайонного разброса есть, но слабый. H3:
  средний сдвиг в целевом интервале, но у 29% затронутых районов переход
  «отменяется» в пределах горизонта модели — часть гипотезы опровергнута
  по собственному контракту пререгистрации.
- **Прогноз 2031+ — не наблюдение.** Зависит от модели населения проекта
  (3 сценария × 2 стартовых ряда); после 2050 — диапазон, не точка.
- **Зарплата/пенсия, зафиксированные на последнем уровне — не прогноз
  экономики.** Изолируют демографический эффект; плоская линия не означает
  ожидание экономической стагнации.
- **G-4 (сверка с UN WPP) не является подтверждением ошибки расчёта.**
  Расхождение объясняется другим определением границы трудоспособности.
