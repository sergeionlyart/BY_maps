## G-3. Бэктест (районы)

Окно **2009→2019** (замена метода — см. `docs/decisions/INF-13.md` и
METHODS.md §7: районного разреза переписи-1999 не существует, поэтому вместо
CCR-модели `etl/forecast/sub.py` (откалиброванной именно на паре 2009-2019 —
бэктест на том же окне был бы самоисполняющимся) используется независимая от
неё проекция «только дожитие»: национальная таблица смертности HMD-2018, БЕЗ
миграции, БЕЗ калибровки к 2019, child-woman ratio из самого 2009 года).

- MAPE модели (survival-only): **8,86%**
- MAPE наивного прогноза (SR заморожен на 2009): **13,93%**
- Модель точнее наивного: **True**
- Доля районов с верно предсказанным знаком изменения: **73,7%** (n=118)
- Требование: точнее наивного **И** доля верного знака ≥ 80%.

**Итог: НЕ ПРОЙДЕНА** (73,7% < 80%, хотя первое условие выполнено с запасом).

Следствие (раздел 13 ТЗ): год перехода порога на районном уровне публикуется
**интервалом** («до 2035» / «2035-2045» / «после 2045»), не точной датой —
поле `crossing_interval` в `pension.json`, ненулевое у ВСЕХ 118 районов
(проверяется `checks/tests/test_invariants.py`, п. 4). Национальный
`crossing_year` НЕ завязан на этот гейт (длинный ряд 1959-2019 + внешняя
сверка G-4) и публикуется точным годом.

Оговорка проверяющего-скептика (`docs/decisions/INF-13.md`, находка E):
проекция «только дожитие» не включает миграцию, в отличие от боевой
CCR-модели (`etl/forecast/sub.py`), которая учитывает её неявно через
эмпирический коэффициент когортного изменения 2009→2019 — G-3 тестирует
более слабый прокси-метод, ошибка знака вероятнее у районов с сильной
миграцией. Непройденный результат остаётся в силе; см. METHODS.md §7.

## G-4. Сверка с UN WPP 2024 (SR-2050)

- Национальный SR-2050 модели (базовый сценарий, официальный старт): **1,52**
  (интерполяция между узлами 2046=1,68 и 2051=1,48)
- UN WPP 2024 medium, потенциальный коэффициент поддержки (15-64/65+), 2050: **2,18**
  (выведен из числителей/знаменателей OWID-зеркала WPP2024, НЕ скопирован
  как готовое значение: `(3876755+1528760-948561)/2046308 = 2,18`, см.
  `data/raw/pension/registry.csv#owid_wpp2024_age_groups`)
- Расхождение: **30,3%**

Расхождение объясняется определением, а не ошибкой расчёта: граница
трудоспособности проекта — законный график (63 муж./58 жен.) — у ОБОИХ полов
НИЖЕ единой константы UN (65 для обоих полов), особенно сильно у женщин (58
против 65). По определению проекта БОЛЬШЕ людей считаются «старше
трудоспособного» (включая всех женщин 58-64 и мужчин 63-64, которых UN
считает ещё «рабочей силой» 15-64), а работающих — меньше: SR проекта
СТРУКТУРНО НИЖЕ UN PSR при том же демографическом составе.

Порог 5% (или письменное объяснение) — **вне допуска, объяснение дано выше**
(обязательное условие раздела 7 ТЗ при провале количественного порога).

## G-5. Чувствительность денежного слоя (CG)

Год 2046, сценарий `base`, n=113 районов с рассчитанным CG (118 минус 5
подавленных гейтом G-7).

| Вариант | Доля районов с тем же знаком (CG≥1 / CG<1) |
|---|---|
| k (охват) +10% | 96,5% (n=113) |
| k (охват) −10% | 99,1% (n=113) |
| b (средняя пенсия) +10% | 96,5% (n=113) |
| b (средняя пенсия) −10% | 99,1% (n=113) |

Минимум по вариантам: **96,5%**. Порог 90% — **пройдена**.

```bash
python3 -c "
import sys; sys.path.insert(0, '.')
from etl.pension import build, gate_g5
b = build()
print(gate_g5(b))"
```

Оговорка проверяющего-скептика (`docs/decisions/INF-13.md`, находка C): для
конкретного района `CG(y) = K_r · SR(y)` — CG не независимый от SR денежный
сигнал, а тот же демографический ряд, пересчитанный в условные деньги при
текущем экономическом масштабе района. Гейт G-5 содержателен, но его точный
смысл — «многие ли районы стоят близко к порогу CG=1», а не «устойчивость
второго, независимого сигнала». См. METHODS.md §4.4, LIMITATIONS.md п. a.

## Дополнительная проверка: H2, относительный и абсолютный разброс SR

Не гейт раздела 7, а честное уточнение к формально подтверждённой H2
(`docs/decisions/INF-13.md`, находка B): единственная замороженная
пререгистрацией метрика — коэффициент вариации `CV(SR)` — растёт, но
абсолютный разброс района от района сужается.

```bash
python3 -c "
import json
d = json.loads(open('web/public/data/pension.json').read())
disp = d['national']['dispersion_sr']
for y in ('2026', '2046'):
    print(y, disp[y])"
```

Ожидаемо: `cv` 0,1907 (2026) → 0,193 (2046) — рост; `sd` 0,3811 → 0,2849
(−25%) и `range` 2,31 → 1,71 (−26%) — сужение. `mean` (средний SR по
стране) падает с 1,998 до 1,476 (−26%) быстрее, чем абсолютный разброс
вокруг него — отсюда и расхождение между относительной (CV) и абсолютной
(sd/range) картиной. См. `claims.yaml` C-009 и `LIMITATIONS.md`, п. k.

## Дополнительная проверка: H3, «отменённые» переходы (за пределами гейтов G1-G7)

Не гейт раздела 7, а прямое следствие контракта опровержения H3 (раздел 7
пререгистрации): при переходе на график 65/60 у части районов, проходящих
порог 1,5 при действующем графике до 2056 года, порог НЕ достигается в
пределах горизонта модели (`policy_delta` становится `null`, а не числом).

```bash
python3 -c "
import json
d = json.loads(open('web/public/data/pension.json').read())
t = d['territories']
raions = [k for k in t if k.startswith('r-')]
group = [r for r in raions
         if (t[r]['crossing']['as_is']['base:official']['1.5'] or 9999) <= 2056]
lost = [r for r in group if t[r]['policy_delta']['1.5']['65_60']['base:official'] is None]
deltas = [t[r]['policy_delta']['1.5']['65_60']['base:official'] for r in group
          if t[r]['policy_delta']['1.5']['65_60']['base:official'] is not None]
print('группа (as_is crossing <=2056):', len(group))
print('с определённым сдвигом:', len(deltas), 'среднее:', round(sum(deltas)/len(deltas), 2))
print('с «отменённым» переходом:', len(lost))"
```

Ожидаемо: группа 93 района, средний сдвиг ≈9,24 года (медиана 9,0 — внутри
интервала [8,12], заявленного пререгистрацией), но 27 из 93 (29%) — с
«отменённым» в пределах горизонта переходом. По собственному контракту
опровержения H3 (раздел 7 пререгистрации: «хотя бы один район ... сдвиг
"отменяет" переход») это означает опровержение части «не отменяет переход
ни в одном районе» — см. `claims.yaml` C-010 и EXECUTIVE_BRIEF.md.
