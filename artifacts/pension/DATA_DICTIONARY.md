# INF-13 «Кто кого содержит»: словарь данных

Пакет `pension` v1.0.0 (2026-07-26). Формулы и параметры — METHODS.md;
допущения — `params/assumptions.yaml`.

**Общие соглашения.** JSON: UTF-8, ключи отсортированы, компактная
сериализация (без пробелов) в `web/public/data/pension.json` — как читает
лендинг; CSV: UTF-8, разделитель — запятая, первая строка — заголовок.
Идентификатор территории `territory_id`: `r-*` (район, слаг латинки
pop-stat), `BY-xx` (область, ISO 3166-2), `BY` (страна). Пустая/`null`
ячейка = «нет данных или не рассчитано» (не ноль). Годы national:
`[1989, 1999, 2009, 2019, 2026, 2031, 2036, 2041, 2046, 2051, 2056]`; годы
territory (районы): `[2009, 2019, 2026, 2031, 2036, 2041, 2046, 2051, 2056]`
(без 1989/1999 — районного разреза советских переписей нет). SR/TDR
округлены до 2 знаков, CG — до 2 знаков, годы — целые.

## 1. `web/public/data/pension.json` — данные сайта (канонический источник чисел)

Верхнеуровневые ключи:

| Ключ | Тип | Содержание |
|---|---|---|
| `version` | строка | `"1.0.0"` — версия модуля `etl/pension.py` |
| `forecast_version` | строка | `"v2026.4"` — версия использованной модели прогноза |
| `generated` | строка | дата генерации файла, ISO `YYYY-MM-DD` |
| `retirement_schedule` | объект | `{год: {m, f}}` за ВЕСЬ график `retirement_age.csv`, 1959-2056 (98 записей — не только переходные 2016-2022) — законный график повышения возраста, чтобы клиентский код не дублировал константы 60/55 (до) и 63/58 (после) отдельным источником истины |
| `policy_variants` | строка[3] | `["as_is", "65_60", "67_62"]` |
| `policy_ages` | объект | `{"as_is": null, "65_60": {m:65.0,f:60.0}, "67_62": {m:67.0,f:62.0}}` — возрастные константы контрфактов |
| `policy_applies_from` | int | `2026` — гипотетические графики применяются только с этого года включительно, задним числом не переписывают историю |
| `contribution_rate` | float | `0.29` — ставка пенсионного страхования (CONTRIB_RATE) |
| `series_keys` | строка[6] | `"<сценарий>:<стартовый_ряд>"`, 3 сценария × 2 старта |
| `thresholds` | float[3] | `[2.0, 1.5, 1.0]` — пороги crossing_year |
| `years` | объект | `{national: [...11], territory: [...9]}` |
| `dtype` | объект | `{national: {год: тип}, territory: {год: тип}}`; типы `c`=перепись, `e`=оценка, `f`=прогноз |
| `national` | объект | национальные ряды (ниже) |
| `territories` | объект | 118 записей `r-* → район` (ниже) |
| `meta` | объект | список claim-ID, имя опубликованного архива, свод результатов гейтов |

### 1.1. `national`

| Ключ | Тип | Содержание |
|---|---|---|
| `sr` | объект | `{policy: {series_key: [11 значений SR по годам national]}}` |
| `tdr` | объект | то же для TDR |
| `crossing` | объект | `{policy: {series_key: {"2.0"/"1.5"/"1.0": год\|null}}}` |
| `policy_delta` | объект | `{"2.0"/"1.5"/"1.0": {"65_60"/"67_62": {series_key: сдвиг_лет\|null}}}` |
| `dispersion_sr` | объект | `{год: {n, mean, sd, cv, min, max, range}}` по 9 годам territory (as_is/base:official, 118 районов) — межрайонная дисперсия SR. `cv` (коэффициент вариации, sd/mean) — единственная метрика, замороженная пререгистрацией для H2; `sd`/`range` добавлены как честное уточнение (находка B проверяющего-скептика, см. LIMITATIONS.md п. k): CV слабо растёт (0,1907→0,193, 2026→2046), но `sd` и `range` СУЖАЮТСЯ (−25%/−26%) — страна сходится к более низкому общему уровню, а не только расслаивается |

`national` НЕ содержит `crossing_interval` — национальный `crossing_year`
точный (не завязан на гейт G-3, см. VALIDATION.md).

### 1.2. `territories[r-*]`

| Поле | Тип | Содержание |
|---|---|---|
| `name` | строка | `"<Название> район"` |
| `oblast` | строка | ISO-код области (`BY-BR`…`BY-MA`) |
| `commute_zone_45min` | bool | `true`, если время до Минска ≤45 мин (`travel_times.csv`) |
| `sr`, `tdr` | объект | как в `national`, но по 9 годам territory |
| `crossing` | объект | точный год перехода (внутренний расчёт; см. `crossing_interval` для того, что публикуется) |
| `crossing_interval` | объект \| null | `{policy: {series_key: {"2.0"/"1.5"/"1.0": "до 2035"\|"2035-2045"\|"после 2045"\|null}}}`; **ненулевое у ВСЕХ 118 районов** в v1.0.0, т.к. гейт G-3 не пройден — публикуемая на сайте версия `crossing_year`, интервал вместо даты |
| `policy_delta` | объект | как в `national` |
| `cg` | объект \| null | `{"<сценарий>:official": {год: CG\|null}}` (только `official` старт — `adjusted` для CG не считается); `null`, если `cg_suppressed` |
| `cg_suppressed` | bool | `true` для 5 районов в зоне 45 мин от Минска (гейт G-7); тождественно `commute_zone_45min` |

### 1.3. `meta`

| Поле | Тип | Содержание |
|---|---|---|
| `claims` | строка[12] | `["C-001", …, "C-012"]` — соответствуют `claims.yaml` этого пакета |
| `artifact` | строка | `"by-maps-pension-v1.0.0.zip"` |
| `validation` | объект | `{G1_national_shares, G2_raion_sum_oblast, G3_backtest, G4_wpp_check, G5_sensitivity: bool; G7_commute_bias: "fallback_applied"; note: строка}` |

`validation.G3_backtest` и `validation.G4_wpp_check` — оба `false` в
v1.0.0 (см. VALIDATION.md); это не ошибка сборки, а честно опубликованный
факт непройденных гейтов с задокументированными следствиями.

## 3. `data/curated/pension_inputs.csv` — входы CG по районам (373 района × метрика)

Регенерируется тем же прогоном. Колонки: `territory_id, metric, year, value, dtype`.

| `metric` | `dtype` | Содержание |
|---|---|---|
| `wage_byn` | `d` (данные) | средняя зарплата района, BYN, по годам 2010-2025 |
| `employed_persons` | `d` | занятые района, чел., по годам 2010-2026 |
| `k_oblast_coverage_2019` | `m` (модель) | коэффициент охвата получателей пенсий области, якорь 2019 |
| `avg_pension_oblast_byn` | `d` | средняя пенсия области, последний наблюдаемый год (2025), BYN |
| `min_minutes_to_minsk` | `d` | время в пути до Минска, мин. (INF-04) |

`dtype='d'` — прямое наблюдение (Белстат/INF-04); `dtype='m'` — модельная
оценка (коэффициент охвата, единственный столбец такого типа в этом файле).

## 7. `data/curated/retirement_age.csv` — законный график (98 строк, 1959-2056)

| Колонка | Тип | Единица | Примечание |
|---|---|---|---|
| `year` | int | 1959-2056 | |
| `retirement_age_m` | float | лет | 60,0 (до 2016) → 63,0 (с 2022) |
| `retirement_age_f` | float | лет | 55,0 (до 2016) → 58,0 (с 2022) |

Годы вне диапазона файла (до 1959 или после 2056) в `age_boundary()`
насыщаются крайним известным значением. Годы ≥2026 при вариантах политики
`65_60`/`67_62` замещаются константой варианта, а не читаются из этого файла.
