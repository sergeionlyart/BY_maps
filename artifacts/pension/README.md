# Кто кого содержит: коэффициент поддержки по 118 районам Беларуси (проверяемый пакет, INF-13, v1.0.0)

## Исследовательский вопрос и главный вывод

Сколько работающих (по действующей в данном году ЗАКОННОЙ границе
трудоспособного возраста, не по фиксированной константе) приходится на
одного человека старше трудоспособного возраста — в каждом из 118 районов
Беларуси, 1989–2056 — и в каком году район проходит пороги 3:1, 1,5:1, 1:1.

**Главный вывод:** демографическая нагрузка расслаивает территорию страны
неравномерно. Национальный коэффициент поддержки (SR) снижается с 2,73
(перепись 2009) до 1,68 (прогноз 2046) и 1,41 (2056); к 2046 году под
порогом SR<1,5 оказываются 69 из 118 районов (58,5%) — против всего одного
района (Кореличского, SR=1,48) уже в 2009 году. Это единственное отклонение
от буквы пререгистрации (ожидавшей ноль районов ниже порога в 2009 году) —
не ошибка расчёта и не спрятано: см. `docs/decisions/INF-13.md` и
`LIMITATIONS.md`, пункт h. Межрайонный коэффициент вариации SR слабо растёт
(0,1907 → 0,193, 2026→2046, H2 формально подтверждена), но абсолютный разброс
(стандартное отклонение) при этом сужается на 25% — страна не столько
расслаивается, сколько сходится к более низкому общему уровню поддержки
(`LIMITATIONS.md`, пункт k). Повышение пенсионного возраста на курс
65/60 сдвигает переход в среднем на 9,2 года, но у 29% затронутых районов
«отменяет» его в пределах горизонта модели — гипотеза H3 честно
опубликована как частично опровергнутая по собственному контракту
пререгистрации (`LIMITATIONS.md`, пункт l). Условная денежная арифметика
(`contribution_gap`, CG) — синтетический сравнительный индекс: ФСЗН
общереспубликанский, отдельных территориальных пенсионных балансов на
уровне района не существует.

## Как воспроизвести

Требования: Python ≥ 3.10 + PyYAML (`code/requirements.lock`) — единственная
внешняя зависимость всего пакета (нужна гейту G-2, который прогоняет
независимый пересчёт области через движок прогноза населения). Время:
несколько секунд.

```bash
bash code/run.sh
```

Скрипт (1) пересчитывает `web/public/data/pension.json`,
`data/curated/pension_inputs.csv` и `docs/notes/pension_validation.md` из
вендоренных источников (`python -m etl.pension`), (2) прогоняет инварианты
(`checks/tests/test_invariants.py`), (3) сверяет 14 контрольных метрик с
`checks/expected_results.json` в объявленных допусках (`code/verify.py`).
Любое расхождение — ненулевой код выхода.

## Как интерпретировать результаты и допуски

- Историческая часть рядов (переписи 1989/1999/2009/2019) — класс CALC:
  детерминированная формула по прямо наблюдаемым данным.
- Прогнозная часть (узлы 2031-2056, все SR/TDR/crossing_year на этих годах)
  — класс MODEL: зависит от базовой демографической модели проекта (3
  сценария × 2 стартовых ряда). После 2050 показывайте диапазон сценариев,
  не единственную точку.
- `contribution_gap` (CG) — класс MODEL ВСЕГДА, целиком, для любого года:
  ни один из пяти компонентов формулы не наблюдается на уровне района
  напрямую. См. `LIMITATIONS.md`, пункт a.
- `crossing_year` района публикуется ИНТЕРВАЛОМ, а не точной датой — гейт
  G-3 (независимый бэктест) не пройден на районном уровне (доля верного
  знака 73,7% при требуемых 80%). Национальный `crossing_year` — точный год.
- Допуски контрольных метрик — `checks/expected_results.json`: 0 для
  целых чисел (годы, счётчики районов), 0,01-0,05 для округлённых
  показателей SR/CG/долей.
- Полный перечень классов утверждений — `claims.yaml` (12 записей,
  DATA/CALC/MODEL/INTERPRETATION/LIMITATION); машиночитаемая сверка —
  `AGENT.md`.

## Честная сводка (что подтверждено, что нет)

Подтверждено: H1 в содержательной части (систематическое расслоение к 2046
году), H2 (слабо), устойчивость знака CG (гейт G-5), сходимость районов и
областей (гейт G-2), национальные доли на 01.01.2025 (гейт G-1). НЕ
подтверждено буквально: H1 в формулировке «ноль районов в 2009» (был один),
H3 в части «не отменяет переход ни в одном районе» (у 27 из 93 отменяет в
пределах горизонта модели), гейт G-3 (бэктест районов), гейт G-4 (сверка с
UN WPP — расхождение объяснено определением границы трудоспособности, не
ошибкой). Ни один из этих исходов не скрыт и не переформулирован под
желаемый результат.
