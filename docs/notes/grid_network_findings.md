# INF-15 «Полотно»: network_per_capita и проверка G-6 — отчёт

**Дата:** 2026-07-26. **Модуль:** `etl/grid_network.py` + `etl/tests/test_grid_network.py`.
**Основание:** ТЗ раздел 4 («метры сети на жителя»), раздел 7 проверка 6 (G-6),
раздел 8 п.4 (снимок, не история); пререгистрация `docs/preregistration/grid-v0.1.md`
§3, утверждение C-3.

Это отчёт по одному изолированному куску работы (метрика network_per_capita
+ проверка G-6 + тест C-3). Он не заменяет и не редактирует
`docs/decisions/INF-15.md` — только фиксирует числовой результат для
дальнейшей интеграции в архив/страницу.

## 1. Официальная статистика протяжённости дорог (шаг 1 ТЗ)

**Основной источник:** РУП «Белдорцентр» (подведомственная организация
Министерства транспорта и коммуникаций Республики Беларусь, ведёт паспорт
сети автомобильных дорог), данные на **01.01.2026**:
<https://beldor.centr.by/en/2026/03/stata2026/> (обращение 2026-07-26).

> Протяжённость сети автомобильных дорог общего пользования — **86 446 км**,
> в т.ч. республиканские дороги — **15 934 км**, местные дороги — **70 512 км**.

**Сверочный источник:** Министерство транспорта и коммуникаций РБ, страница
«Сеть автомобильных дорог» (без явной даты публикации на самой странице):
<https://mintrans.gov.by/ru/dorozhnoe-khozyajstvo/struktura/set-avtomobilnykh-dorog>
(обращение 2026-07-26) — **86 538 км** (респ. 15 944 + местные 70 594 км).

Два официальных источника расходятся между собой на **0,1%** (86 446 vs
86 538 км) — в пределах обычного лага обновления реестра между двумя
ведомственными публикациями. Для G-6 взята более свежая по явной дате цифра
Белдорцентра (01.01.2026) как основная; выбор между двумя источниками не
влияет на исход проверки (расхождение источников на два порядка меньше
допуска G-6 в 15%).

Зарегистрировано в `data/raw/grid/registry_road_stats.csv` (id, title, url,
license, accessed, value, notes — та же схема колонок, что у
`data/raw/grid/registry_ghsl_pop.csv`).

**Важное методическое ограничение**, честно зафиксированное в коде и здесь:
снимок дорожного графа INF-04 (`data/raw/osm/graph_edges.csv.gz`) извлекался
только под нужды межрайонного travel-time и содержит **только**
motorway/trunk/primary/secondary/tertiary (+`_link`-варианты) — классы
residential/unclassified/track в нём отсутствуют по построению (см.
`data/raw/osm/registry.csv` и docstring `etl/osm_graph.py`). Официальная
статистика включает ВСЕ дороги общего пользования, включая местные
проездные. Прямое сопоставление классов («республиканские» ~
motorway/trunk, «местные» ~ primary/secondary/tertiary) невозможно один в
один — это разные классификационные шкалы (административная vs
функциональная). Поэтому сравнение сделано только по общему итогу против
общего итога (защитимый вариант, прямо предусмотренный заданием на этот WP).

## 2. Итог G-6: полнота карты дорог

| | км |
|---|---|
| OSM (снимок INF-04, только 5 классов + `_link`) | **76 958,8** |
| Официальная статистика (Белдорцентр, 01.01.2026) | **86 446,0** |
| Δ | **−10,97%** |
| Допуск (Приложение А ТЗ) | ±15% |
| **Результат** | **G-6 ПРОЙДЕНА** |

`mode = "absolute"` в `network_metrics.json` — то есть `network_per_capita`
публикуется с абсолютными числами (км/1000 жителей, км/км²), а не только как
относительный индекс.

Разбивка OSM-итога по классам (км): motorway 1013,3 (+109,2 `_link`),
trunk 4471,2 (+447,6 `_link`), primary 13257,8 (+154,7 `_link`),
secondary 7887,7 (+23,8 `_link`), tertiary 49559,2 (+34,3 `_link`) — tertiary
доминирует (64% всей длины снимка), что и объясняет, почему итог всего на
11% ниже официального «всех дорог общего пользования»: в Беларуси заметная
часть официальных «местных дорог» — это асфальтированные межхозяйственные дороги,
которые OSM-картографы обычно тегируют как `tertiary`, а не `residential`.

Прочтение результата: пройденный G-6 здесь — **робастный**, не «на грани».
Если бы снимок INF-04 включал ещё и residential/unclassified/track (сейчас
не извлечены — вне рамок этого WP), OSM-итог мог бы только вырасти, то есть
Δ приблизился бы к нулю, а не ушёл за допуск. Односторонний риск (снимок
неполон) работает в пользу прохождения проверки, а не против него.

## 3. Проверка C-3 (пререгистрация §3)

**Гипотеза:** `network_per_capita_2026` (км дорог на 1000 жителей) выше там,
где депопуляция 1989→2026 сильнее. Тест — корреляция Спирмена по 118
районам (без BY-HM, как зафиксировано в тексте пререгистрации).

| | значение |
|---|---|
| Spearman ρ | **−0,7508** |
| p-value | **1,25 × 10⁻²²** (scipy.stats.spearmanr) |
| n | 118 районов |
| Знак | отрицательный |
| Значимость (α=0,05) | значима |
| **Итог** | **C-3 подтверждается** |

Корреляция не просто отрицательна и значима — она сильная (|ρ| = 0,75 из
118 наблюдений), что для межрайонных социально-географических сопоставлений
редкость. Данные фактические: численность 1989/2026 из
`web/public/data/data.json`, площадь района — оттуда же (`territories[tid].area`),
длина сети — сумма по всем классам OSM-снимка на середину каждого ребра
(point-in-polygon по adm2 r-*/adm1 BY-HM).

**Два района потребовали резервный год численности** (зафиксировано,
не скрыто — `is_fallback: true` в `network_metrics.json`):

- **r-drybinski** — нет записи за 1989 год; взят ближайший **последующий**
  переписной год (1999, согласно правилу раздела 4 пререгистрации).
- **r-chervienski** — нет записи за 2026 год; взят ближайший **предыдущий**
  доступный год (2025).

**Честная оговорка про механизм (не только для красоты вывода).** Часть
этой корреляции может быть почти механической: дорожная сеть — это
пространственно-протяжённая инфраструктура с более-менее фиксированной
плотностью на км² (советское наследие сети местных дорог), а
network_per_capita = длина сети / население — при падающем знаменателе
растёт почти арифметически при любом типе убыли, не только при
«убегающей» депопуляции конкретно с 1989 года. Другими словами: сильная
корреляция здесь ожидаема почти по построению метрики (население меньше →
делитель меньше → частное больше), и её нельзя без оговорки подавать как
открытие новой причинно-следственной связи — это тот же класс
предупреждения, что раздел 7 пререгистрации делает для C-1 (альтернативные
механизмы, подлежащие проверке до интерпретации). Раздел 8 ТЗ п.4 отдельно
требует: по дорогам у нас снимок на 2026 год, а не история — корректно
говорить «сейчас на депопулирующих территориях сети на человека больше», и
некорректно говорить, что «сеть выросла» или что депопуляция «вызвала»
нагрузку — причинных глаголов в этом отчёте намеренно нет.

Отдельная задача из контракта опровержения C-3 (§7 пререгистрации) —
пересчитать корреляцию **после исключения городских районов INF-12** — в
этот WP не входила (базовая корреляция уже посчитана и зафиксирована;
доп. проверка не требуется контрактом, если базовая корреляция УЖЕ
подтверждает C-3 — здесь так и есть, но при интеграции в архив
исследования эту проверку на устойчивость стоит выполнить отдельным
шагом, если понадобится доп. подтверждение).

## 4. Районы-выбросы

**Самая низкая нагрузка на жителя** (плотные/пригородные районы вокруг
областных центров, а не Минска):

| Район | км/1000 жит. | Δpop 1989→2026 |
|---|---|---|
| r-homielski | 1,65 | −4,0% |
| r-brescki | 2,35 | +30,6% |
| r-mahilouski | 2,69 | −5,5% |
| r-viciebski | 3,02 | −4,3% |
| r-hrodzienski | 3,61 | +20,9% |

**Самая высокая нагрузка на жителя** (глубокая периферия, почти все —
северная часть Витебской области):

| Район | км/1000 жит. | Δpop 1989→2026 |
|---|---|---|
| r-svislacki | 43,98 | −59,7% |
| r-ushacki | 45,08 | −53,1% |
| r-siennienski | 46,15 | −55,1% |
| r-iujeuski | 46,39 | −55,6% |
| r-rasonski | 58,83 | −48,7% |

Из 118 районов только **6** выросли по численности с 1989 года — все
пригородные/прилегающие к Минску или областным центрам: r-minski +94,7%
(6,79 км/1000, индекс 0,31 от среднего по районам), r-brescki +30,6%
(2,35; индекс 0,11), r-dziarzhynski +21,4% (11,86; индекс 0,54),
r-hrodzienski +20,9% (3,61; индекс 0,16), r-smalavicki +18,7% (7,18;
индекс 0,33), r-mazyrski +0,6%, почти без изменений (3,97; индекс 0,18).

Частичный выброс внутри этой группы — **r-dziarzhynski**: растущий район
(+21,4%), но с почти вдвое более высоким network_per_capita, чем у
остальных растущих районов (11,86 км/1000 против 2,35–7,18 у остальных
пяти). Это всё ещё заметно ниже среднего по районам (индекс 0,54 от
среднего, то есть ниже 1,0 — не противоречит общему тренду C-3), но внутри
самой группы «растущих» районов он выделяется. Правдоподобное объяснение
не проверялось отдельно в этом WP: Дзержинский район — не собственно
пригород областного центра, а район с рассредоточенной сетью малых
городов (Дзержинск, Фаниполь, Негорелое) без такой же концентрации
населения, как у прямых спутников Минска/облцентров. Не искажает общий
вывод (ранговая корреляция устойчива к единичным отклонениям при n=118),
но стоит держать в поле зрения при дальнейшем анализе.

Национальный итог: `road_km_per_1000 = 8,498` (по сумме 119 зон; см.
оговорку в `network_metrics.json → national.pop_current_total_note` о том,
что эта сумма населения — по периметру 119 зон nightlights-конвенции
проекта, не полная численность страны, т.к. население отдельных
областных/районных городов учтено в data.json отдельными территориями).

## 5. Технические детали / ограничения реализации

- **Геопривязка рёбер:** середина ребра (арифметическое среднее lat/lon
  концов, не геодезический midpoint — оправдано короткой типичной длиной
  ребра, см. ниже) проверяется на `covered_by` (включает границу) против
  118 полигонов adm2 `r-*` + полигона BY-HM (adm1), наложенного последним —
  тот же принцип «рисуем поверх», что в
  `etl/nightlights_extract.py::_zone_labels`, только через shapely
  point-in-polygon (STRtree), а не растеризацию.
- **0,82% рёбер (6822 из 833 438)** не попали ни в один полигон через
  `covered_by` — расхождение клип-границы Geofabrik-выгрузки OSM и
  adm2-полигонов проекта (медианное расстояние до ближайшего полигона
  ≈1,2 км, максимум у выборки ≈22 км). Такие рёбра присвоены ближайшему
  району (`STRtree.nearest`), не потеряны и не выброшены — учтены отдельно
  в `national.n_edges_snapped_to_nearest`.
- **408 рёбер** лежат точно на общей границе двух районов — присвоены по
  приоритету последнего в списке полигонов (детерминированно, но
  геометрически произвольно для пар районов, не участвующих в наложении
  Минск/Минский район); доля пренебрежимо мала (0,05%).
- **Длина ребра** — гаверсинус по (lat_a,lon_a)→(lat_b,lon_b), т.к. в
  снимке не хранится (см. docstring `etl/osm_graph.py`).
- Spearman посчитан через `scipy.stats.spearmanr` (scipy 1.17.1 доступен в
  `.venv` этого репозитория как опциональная зависимость для растровых
  шагов) — в `etl/grid_network.py` есть ручной fallback (ранги + continued
  fraction для incomplete beta, без scipy) на случай окружения без scipy,
  но в этом прогоне не использовался.
